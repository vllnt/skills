## Method

1. Select affected cases; inspect source instructions, not descriptions.
2. Give an independent evaluator the request and fixture, not the expected decision; load only the relevant workflow and its on-demand references.
3. Observe real actions where a safe harness exists; otherwise label the result **instruction-following simulation**, not runtime verification.
4. Compare actions and output with the acceptance column; prose alone does not establish filesystem, browser, service, or merge behavior.
5. Exercise a working path and a missing prerequisite; rerun after edits; rework the owning skill rather than weakening the case.

Verified partial work plus a precise remaining external condition is useful output; missing optional tooling must not cause a user interview, bypassed authorization, or fabricated proof. Record per case: skill hashes, observed actions, result, evidence path, limitation; separate executed checks from simulations; a dry run does not prove live deployment or merge behavior.

## Rules, naming, and structural checks

- Rules fixture (user, project, nested): remove redundant constraints; keep deliberate formatting overrides and read-only user sources. A conflicting project-only repair finishes locally and proposes the global fix with its impact; no global rule changes. A missing linked source or unknown runtime precedence keeps the rule, reports the discovery check, claims no equivalence.
- Code-review and code-tests references on one candidate: findings versus authorized checks with provenance; neither grants merge approval.
- Every `<category>/<skill>/SKILL.md` has valid frontmatter and a name matching its folder; discovery includes only workflows and mandatory folders and rejects duplicate public names and SKILL.md or frontmatter in reference trees.
- Workflows and reference procedures have mode-specific observable completion criteria and bounded rechecks; validation rejects criteria after procedure, a repeated body title, a reference without effects, and a task workflow in a mandatory entry.
- Retained local links resolve; optional siblings are not assumed installed; loading dependencies have no cycles (review/repair loops are not); changing, removing, or unlinking a canonical reference makes bundle checks detect stale, missing, or unused copies and regeneration yields only required closure.
- Catalog entries match files; contributor policy matches `AGENTS.md`; public artifacts hold no credentials, private application details, or user-system paths.
