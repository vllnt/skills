## Goal

Return an actionable plan, or in decision mode an improved artifact, evidenced recommendation, or bounded unknown, without local or remote side effects or changing the subject. Execution resumes only with explicit authority for the stated scope.

### Definition of Done

- Mode (plan, or decision: refine an artifact, compare alternatives, or examine an evidence gap), scope, candidate, facts, assumptions, gaps, owners, interfaces, and criteria are explicit.
- A plan is proportional, not exhaustive: ordered work, dependencies, outcomes, future checks, risks, and recommendations, with detail only for the first verifiable steps and their proof. A decision result recommends by default, adding a counterargument for a decision or exact proposed wording for an artifact where useful.
- Reversible choices are decided and noted; other open forks are settled by a discriminating check, or the exact remaining decision is named with a recommended answer. A question appears only for a material evidence gap or a user-only choice.
- No local or remote mutation, execution, or boundary bypass occurred.
- Current validation accepts the result; no required finding remains.

## Boundaries

- Do not write state (including the subject of a decision), run unbounded-effect tools, or delegate around the read-only boundary. Proposed edits stay advisory; agreement on a plan or recommendation is not execution authority.

## Workflow

1. Inspect only safely readable evidence. Resolve mode, outcome, scope, constraints, applicable instructions, loaded principles, and the validation contract.
2. Plan mode: produce the simplest ordered work with dependencies, outcomes, future checks, risks, and recommendations. Plan only as deep as the next decision needs: detail the first verifiable steps and their proof, outline the rest, and stop when the next step and its proof are clear. For code work, use [Code review](references/vstack/capabilities/code-review/REFERENCE.md) in plan mode to name the applicable perspectives, the runnable proof for each, and any missing proof script or check to add. Tag each baseline row universal, conditional, or optional with its source. Trace each planned topology to its files, commands, and verification target. Decision mode: inspect the subject, recommend and proceed by default, and test the recommendation against the artifact and rules. In both, decide each reversible choice by lowest lifetime cost (fastest verified delivery, simplest long-term maintenance, best developer and agent experience) and note it; skip option matrices for them.
3. For a consequential choice that evidence or a discriminating check cannot settle and that needs the user (missing authority, access, irreversible or high-risk effect, or preference), return one batched question set (decision mode: up to four questions on one gap) with options, a recommended answer, the consequence, and the exact decision needed. Do not ask for routine confirmation.
4. For substantive work, use [Quality validation](references/vstack/protocols/quality-validation.md) in read-only mode; name any prototype or check to run once execution is authorized, and settle open decision questions with a read-only discriminating check, else propose the prototype.
5. Revise only after changed evidence or a discriminating check. On unchanged evidence, change approach or return the cause, options, recommendation, consequence, and next action.
