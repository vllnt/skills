# Manage Skills

Maintain portable skills while consumer repositories retain placement, commands, permissions, and delivery policy. Use the repository-local `manage-skill` only to maintain this collection.

## Workflow

1. Confirm outcome, scope, owner, effects, callers, applicable user, project, and nested rules, loaded principles, completion proof, and whether an existing skill owns the capability. Before producing a substantive skill candidate, define its validation contract: candidate, mode, Definition of Done, criteria, evidence, and useful perspectives.
2. For assessment/planning, inspect and propose only. For authorized CRUD, prepare the smallest distinct candidate and resolve callers before retirement.
3. Write reusable trigger, inputs, effects, procedure, completion evidence, blockers, coverage/failure handling, and Definition of Done; discover consumer policy at use time.
4. Recommend the smallest candidate and expected consequence. Decide reversible maintenance details from evidence; ask only for missing authority or a consequential choice.
5. Validate metadata, path/name, references, callers, commands, final diff, success scenarios, and failure/partial-discovery scenarios.
6. For a substantive skill candidate, use [Quality Validation](../../capabilities/capability-quality-validation/SKILL.md). If unavailable, self-assess; obtain distinct review and critique with subagents, or assess them sequentially only when independence is not required; otherwise return BLOCKED. Triage findings, repair the candidate, and request fresh affected verdicts until PASS. Use direct checks for mechanical work. Recheck only after changed evidence or a repair; on unchanged evidence, change approach or return the cause, options, recommendation, consequence, and next action.

## Definition of Done

- Outcome, owner, effects, callers, and portability boundary are explicit.
- Definition of Done has observable success and blocked/failure criteria.
- Assessment/planning changes nothing.
- Authorized changes retain valid metadata, callers, scenario evidence, and gaps.
- Completion requires current mode-specific acceptance: every required criterion has proof, applicable review and critique scopes accept, and no required finding remains.
