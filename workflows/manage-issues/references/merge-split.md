# Merge and Split Issues

One issue owns one independently deliverable outcome.

1. Compare outcome, evidence, acceptance checks, dependencies, and current ownership.
2. For duplicates, recommend a canonical issue, preserve unique context, cross-link it, and close others only with authority and a recoverable reason.
3. For compound issues, create a child per independently deliverable outcome. Preserve the original context and link parent and children through the consumer's supported mechanism.
4. Keep a tracking parent only when it owns the combined outcome; otherwise close it after every child is linked and its remaining work is empty.

Similar wording is not enough to merge. Coupled changes are not enough to split.
